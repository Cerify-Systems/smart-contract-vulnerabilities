# Summary
Grim Finance was exploited on December 18, 2021 through a reentrancy vulnerability in the `GrimBoostVault` `depositFor()` function. The function accepted a caller-controlled token address and called that token's `safeTransferFrom()` before minting vault shares. A malicious token could therefore re-enter `depositFor()` during the external transfer. Because each nested call calculated its pool balance before the final legitimate transfer was reflected, the same increase in vault balance could be used repeatedly when calculating shares. This inflated the attacker's GB share balance and allowed withdrawal of more SPIRIT-LP tokens than had actually been deposited. Public analyses report approximately $30 million in losses. The attack used a flash loan to create the initial LP position, but the core vulnerability was the reentrancy and arbitrary token input in `depositFor()`.
